# 技术待办与未决事项

本文件跟踪尚未确定的技术选型与公共约定，不是需求文档，也不记录普通功能开发任务。

## 使用规则

- 只收录会影响长期维护、公共行为、运行模型或多个模块的未决事项。
- 事项确认后写入 `docs/decisions.md`，并删除本文件对应条目；方向变化或事项取消时直接更新或删除。
- 未确定前，不在代码或文档中自行设定相关规范。
- 「位置与方向已定、细节未定」的事项，已定部分以 `docs/decisions.md` 为准，本文件只跟踪剩余细节。

## 未决事项

### 持久层框架选型

- 问题：选用哪套持久层框架（MyBatis 系、JPA 系等）。
- 状态：待确认。框架未定前，业务模块持久化访问包名用 `mapper/` 或 `repository/` 均可作为预留表述，不预建物理包，也不预建 `infra/persistence/`。
- 影响：各业务模块持久化实现方式、访问类命名、`infra/persistence/` 内容。

### 权限框架选型

- 问题：选用哪套权限框架（Spring Security、Sa-Token 等）。
- 状态：待确认。无认证需求时不引入依赖、不预建 `infra/security/` 空包；选用时按当前版本官方文档配置，不照搬旧版 API。
- 影响：`infra/security/` 实现方式、登录态与鉴权横切写法。

### 虚拟线程

- 问题：是否启用 `spring.threads.virtual.enabled=true`，让 Tomcat 请求线程、`@Async`、`@Scheduled` 改用虚拟线程。
- 状态：待确认。属于运行模型变更，启用前需评估与权限框架、持久层连接池等组件的兼容性；未确认前保持框架默认。
- 影响：线程模型、并发行为、连接池配置、性能特性。

### API 路径风格

- 问题：是否采用 RESTful 加版本前缀（`/api/v1/<resource>`），或不加版本前缀，或按业务动作命名。
- 状态：待确认。现有示例接口为 `/hello`。
- 影响：接口路径命名、版本演进策略。

### 异常分类与错误响应字段

- 问题：业务异常与系统异常如何分类，以及统一错误响应的具体字段。
- 状态：统一管理方式与包位置已确认，见 `docs/decisions.md`「采用模块化单体架构」异常体系条款；本项只跟踪分类方式、错误码划分与错误体字段。
- 进展：全局异常处理器（`infra/exception` 的 `@RestControllerAdvice`）计划下一步落地；落地后字段必填/格式类校验采用 Jakarta Validation（`@NotBlank` 等注解 + `@Valid`），统一映射为 `ResultEnum.VALIDATION_FAILED`（422）。落地前的临时做法：字段校验在 Service 手写 `Result.fail(code, msg)`，业务规则校验固定用 `Result.fail(业务子码, msg)`。
- 影响：公共错误响应一致性、业务抛错方式、与全局返回参数字段的衔接。

### 全局返回参数的排查字段

- 问题：全局返回参数是否增加链路 ID（`traceId`）与调试用异常详情字段，以及各自的来源、开关和生效环境。
- 状态：暂不引入。`Result<T>` 当前字段见 `docs/decisions.md`「公共 API 全局返回参数」。链路 ID 需先确定日志与链路追踪方案；调试详情涉及异常信息对外暴露范围，须与全局异常处理和环境开关一并设计。
- 影响：`Result<T>` 字段与序列化结果、全局异常处理写法、日志与排查流程。
